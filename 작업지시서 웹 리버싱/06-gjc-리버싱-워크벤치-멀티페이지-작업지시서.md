# gjc 리버싱 워크벤치 작업지시서 — 범용 멀티페이지 크롤 엔진

## 1. 목표

단일 URL 추출을 사이트 전체(멀티페이지) 클로닝으로 확장한다.
**특정 사이트에 종속되지 않는 범용 엔진으로 구현할 것.** t-print는 첫 번째 검증 케이스일 뿐,
t-print 전용 하드코딩은 금지.

## 2. 배경

- 현재 `extract-frontend`는 단일 URL만 처리하고 `<a href>`를 손대지 않는다.
  결과 클론은 메뉴 클릭 시 갈 데가 없는 외딴섬 1페이지가 됨.
- 사이트마다 URL 체계·규모·링크 방식이 다르므로, 크롤 범위와 규칙을 설정값으로 분리한
  엔진이 필요하다. 사이트별 분기는 설정값으로 흡수하고 코드 분기는 만들지 않는다.

## 3. 스펙

### 3.1 크롤 설정 (crawlConfig)

UI에서 지정 가능, 아래 기본값 포함:

| 항목 | 기본값 | 설명 |
|---|---|---|
| startUrl | (현재 입력값) | 크롤 시작 URL |
| maxDepth | 2 | startUrl=0, 메뉴=1, 하위=2 |
| maxPages | 100 | 안전 상한 |
| includePatterns | [] | 포함 URL 문자열 (비어 있으면 전체) |
| excludePatterns | login, cart, order, mypay, member, write | 제외 URL 문자열 (사용자 추가 가능) |
| sameOriginOnly | true | 외부 도메인 수집 여부 |
| delayMs | 1500 | 페이지 간 추출 간격 |
| paramBlacklist | timeKey | 정규화 시 제거할 쿼리 파라미터 (사용자 추가 가능) |
| waitForSelector | (없음) | SPA 대비 렌더 대기 셀렉터 (후속 확장용, 이번엔 받기만) |

### 3.2 Phase 1 — 링크 수집

- 시작 페이지 DOM에서 same-origin `<a href>` 수집 (상대경로는 절대URL로 해석).
- URL 정규화: fragment(`#...`) 제거, paramBlacklist 파라미터 제거, 말미 슬래시 통일.
- '전체상품' 같은 JS 토글 메뉴: 클릭 시뮬레이션 없이 HTML에 이미 포함된 하위 `<a>`를
  직접 수집한다.
- `target=_blank` 외부 링크·SNS 공유 링크는 수집에서 제외.

### 3.3 Phase 2 — 범위 필터

- excludePatterns에 매칭되는 URL 제외.
- maxDepth 적용, 정규화된 URL 기준 중복 제거.
- 수집된 URL 목록을 UI에 미리 보여주고 **사용자 확인 후 추출 시작**
  ("N개 페이지 수집됨" 표시).

### 3.4 Phase 3 — 순차 추출

- 기존 CDP 파이프라인(extract-frontend 내부 로직)을 페이지 단위 함수로 분리해 재사용.
- 한 번에 1페이지씩, delayMs 간격으로 순차 처리 (원본 서버 부하 방지).
- **에셋 중복 제거**: assetUrls의 URL 기준 전역 Map을 두고, 같은 URL은 한 번만 저장.
  여러 페이지가 같은 localPath를 참조한다.
- 실패한 페이지는 failedPages에 기록하고 계속 진행 (전체 중단 금지).

### 3.5 Phase 4 — 링크 재작성

- `urlmap.json`: 정규화 URL → 로컬 파일 경로 매핑표 생성.
- 각 페이지 HTML의 `<a href>`를 수집된 페이지에 한해 로컬 상대경로로 재작성.
- 수집되지 않은 링크(제외된 페이지·외부 URL)는 원본 절대 URL 그대로 유지.
- 파일명 규칙: URL 경로 basename + 주요 쿼리 파라미터
  (예: `goods_list_26010000.html`, `POD_goods_73.html`, `board_49.html`),
  충돌 시 6자리 해시 suffix 추가.

### 3.6 Phase 5 — 출력 구조

```
clone_<도메인>_<YYYYMMDD-HHmm>/
  index.html              (시작 페이지)
  pages/
    goods_list_26010000.html ...
  css/  assets/           (전 페이지 공용)
  urlmap.json             (원본 URL → 로컬 파일)
  manifest.json           (원본 URL, 추출 시각, 페이지 목록, 실패 목록, 에셋 목록)
  README.md               (열람 방법)
```

### 3.7 UI 변경

- [프론트 추출] 탭에 [멀티페이지 추출] 모드 추가:
  시작 URL 입력, 깊이 선택 (1=메뉴만 / 2=하위까지), 최대 페이지 수,
  제외 패턴 추가 입력.
- 추출 전 "N개 페이지 수집됨" 확인 표시 + [추출 시작] 버튼.
- 진행 로그: "페이지 추출 중... (3/42)" 형식 + 실패 페이지 기록.

## 4. t-print 검증 케이스

- 범위: 메인 + 메뉴 9 + 상품상세 18 + 게시판 목록 9 + 정적 5 = **약 42페이지**.
- 게시판 글 본문은 제외 (1만+ 글, 비밀글 다수 — 목록까지만).
- 기대 결과: 42개 HTML + 공용 에셋, 클론 내 메뉴 클릭 시 로컬 페이지 간 이동 동작.

## 5. 완료 기준 (자체 검증 후 보고)

- [ ] t-print 42페이지 추출 성공 (실패 페이지는 manifest.json에 기록).
- [ ] 클론의 메뉴 클릭이 로컬 페이지로 이동함.
- [ ] 에셋 중복 저장 없음 (같은 URL → 같은 파일 하나).
- [ ] 제외 패턴(login/cart 등 포함 URL)이 수집 목록에서 빠짐.
- [ ] maxPages 상한이 동작함.
- [ ] 기존 단일 페이지 추출 모드도 여전히 동작함.

## 6. 주의사항

- safe-shell 스킬 준수.
- diagnose-first: 패치 전 원인 가설과 설명부터.
- 원본 서버에 과도한 부하 금지 (순차 1개씩 + 간격 준수).
- t-print 전용 하드코딩 금지. 사이트별 차이는 crawlConfig 값으로만 흡수.
- 완료 보고 전 체크리스트를 직접 실행해서 확인한 뒤 보고할 것.
